# Tool execution contract

**Status: implemented-partial.** This contract describes existing boundaries alongside explicitly identified limitations.

All model-selected operations must cross the trusted broker. Text generated by a model is an invocation proposal, not permission.
## Current model tools
- skill_read supplies advisory instructions. workspace_list and workspace_read provide bounded reads.
- workspace_write requires a permitted relative path and approval when policy requires it.
- workspace_command executes only allowlisted argv under its permitted sandbox and time/output limits.
- native_tool invokes the twelve bounded native metadata capabilities; it cannot independently run arbitrary tests or commit external side effects.
- Governed MCP calls currently use a separate CLI gateway, not a general model-facing MCP tool.
## Enforcement sequence
1. Validate tool name, closed JSON arguments, invocation correlation and canonical resource.
2. Evaluate identity, effective policy, contract, scope, classification, budget and approvals.
3. Durably journal pre-effect decision; refuse if required audit is unavailable.
4. Execute only the declared operation; classify and redact results; journal the outcome.
## Error and replay rule
- Malformed or unknown tools deny. Ambiguous remote outcomes require source reconciliation, never a blind retry.
- Test runners can execute attacker code. A command allowlist is not a sandbox.
## Acceptance
- Prove rejection of malformed arguments, cross-scope file changes, unauthorized native effects, approval reuse and secret-bearing outputs.

## Change control
Source modifications require documentation review and negative tests. Neither passing compilation nor an AI claim alone proves runtime enforcement.
